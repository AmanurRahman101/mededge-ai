# Local extraction architecture for Bangladeshi prescriptions

Research snapshot: 28 October 2026. The proposed models are candidates, not a measured ranking on the project's prescriptions; no patient images were sent to any service in this research.

## Decision for MedEdge

Choose a hybrid pipeline: OpenCV quality/geometry checks -> local PaddleOCR-VL-1.6 document-parser candidate -> editable, confirmed redaction -> existing configured Meta vision extractor reading the whole page and high-resolution section crops -> evidence/coverage reconciliation -> clinician review -> deterministic FHIR assembly. This assumes redacted cloud processing is acceptable; the user's deployment preference is pending. A fully local variant replaces the Meta vision calls with a local VLM server. These are engineering choices to benchmark, not claims of established prescription accuracy.

The supplied prescription contains a printed bilingual provider header, patient/date line, left-side notes and tests, right-side medication groups with Bengali instructions, signature/date and a printed clinic footer. It cannot be reduced to a single table. Preserve all sections and their associations. Keep the supplied original outside the repository; no new inference or model downloads were performed.

## Proposed pipeline

1. **Capture and quality check locally.** Keep the original full-resolution image; check for clipped edges, glare, blur, skew and insufficient detail. Show retake guidance rather than inventing missing content. Retain transforms mapping preprocessed coordinates back to the original.
2. **Layout and local privacy boundaries.** Detect page, printed headers, patient identifiers, medicine rows, notes and footer. Store the full original and any complete transcription only within a private, access-controlled scope. Redact identifiers before any external processing. Provide editable boxes, because detector results and identifiers are not guaranteed complete. Default remote SAM sends the original before redaction; use configured local segmentation or another local detector for a fully local design.
3. **Read at two scales.** Run a whole-page pass to preserve layout, reading order and relationships; run high-resolution overlapping crops around each text line/medicine row and difficult header/advice areas. Map each crop and field to original page coordinates. Preserve raw verbatim Bengali/English, uncertain characters, source image references, alternative readings and provenance. Compare passes and flag discrepancies or missing regions instead of merging silently.
4. **Structured extraction with evidence.** Group text into patient/clinician details, date, medicines, printed instructions, handwritten timing/advice, tests, and other text. Capture all observed content verbatim locally, including content outside the current product policy. Maintain a separate explicitly allowed output for sharing/FHIR; patient identifiers and diagnosis-like text must not be automatically exported. Store each value's bbox, raw text, alternatives, review status, and model/version. Include unclassified text so no content silently disappears.
5. **Medication candidates, not correction.** Search a versioned licensed Bangladesh brand/generic catalog locally to provide possible matches, preserving source spelling. Do not silently replace names or infer strength, dose, duration, timing, route, missing text, diagnoses or treatment. Catalog suggestions must be optional and distinguishable from observed transcription.
6. **Human review.** Display source crop and transcription together; highlight missing/uncertain text, disagreements and catalog candidates. Require explicit reviewer confirmation of drug, strength, frequency, timing and duration before any medication export; unresolved values remain unknown. A model-generated confidence is not a guarantee, so do not auto-accept on confidence alone.

## Candidates to benchmark

- **Qwen3-VL 8B Instruct, run locally:** reasonable first full-page and high-resolution crop transcription/structuring candidate; official project describes multilingual OCR and offers 8B weights. Its claims are not a Bangladeshi handwritten prescription benchmark and do not establish Bengali accuracy. Check actual RAM/VRAM, throughput, license and quantization accuracy on the target hardware. [Official Qwen3-VL](https://github.com/QwenLM/Qwen3-VL/blob/main/README.md).
- **PaddleOCR-VL 1.6:** first local document-parser candidate. Version 1.5 explicitly added Bengali, text spotting and photographed-document handling; 1.6 builds on it and reports improved general parsing. This is a different pipeline from standard PP-OCRv5/v6 and the currently installed old RapidOCR package. These claims do not establish Bengali prescription handwriting accuracy. [1.5 official model card](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.5), [1.6 official model card](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6).
- **Qwen3.5-9B:** compare against Qwen3-VL-8B for the fully local alternative. Its official card provides image-to-text weights, local serving instructions and general OCR/document benchmarks; these do not determine performance on this prescription. GPU, quantization and latency must be measured on target hardware. [Official model card](https://huggingface.co/Qwen/Qwen3.5-9B).
- **Configured Muse extractor:** provisional hybrid handwriting reader, using the project's existing `muse-spark-1.3` configuration for whole-page inventory and focused section rereads. Keep this for the Meta hackathon integration; access and model availability must be checked when credentials are supplied. No live prescription test has established its accuracy. [Meta multimodal Muse description](https://ai.meta.com/blog/introducing-muse-spark-msl).
- **EasyOCR Bengali+English** and current RapidOCR/PP-OCR for printed text are inexpensive baselines, not evidence of handwriting suitability. [EasyOCR source](https://github.com/JaidedAI/EasyOCR/blob/master/easyocr/easyocr.py).
- If local evidence supports it, investigate a specialized handwriting recognizer trained on consented Bangladeshi examples. Published Bangladeshi work used a bounded vocabulary and a specific dataset, so its reported performance does not generalize automatically to arbitrary whole prescriptions. [Study](https://pmc.ncbi.nlm.nih.gov/articles/PMC8897401/).

## Evaluation before selecting a winner

Annotate a representative local set with full-page transcriptions, field-level boxes and expert consensus, capturing uncropped images across doctors, sites, devices, layouts, Bengali/English, handwriting, skew and lighting. Split train/validation/test by **writer and preferably clinic/template**, not random crops, so familiar handwriting or forms do not leak. Use an untouched test set and record uncertainty and reviewer disagreement. A public [1,000-image bilingual prescription dataset](https://data.mendeley.com/datasets/compare/tg2hm7n2bs) may supplement testing, after verifying permissions, redaction, provenance and split suitability; it does not replace local representative data.

Measure identifier redaction recall and coverage; exact medication brand, strength, dose, duration and timing correctness; hallucination and omission rate; Bengali/English transcription CER/WER; linking instructions to the correct medicine; uncertain-field detection; reviewer correction time; memory and latency on intended hardware. Separate printed from handwritten performance. Define release thresholds with domain reviewers and inspect errors, especially clinically significant substitutions. Raw characters and evidence need independent expert annotation: existing bundle verification only checks consistency with extracted data, not fidelity to the image.

## Required changes in the existing app

- Branch prescription and lab flows in `orchestrator.py`. Replace the single `table_png or redacted_png` extraction with a section inventory and multi-region reads. Keep medicine name/dose/Bengali continuation together in each crop. Bound retries by cost and latency.
- Expand `schemas.py`: provider/clinic, private patient fields, date, clinician-written source notes, medications, tests, advice/follow-up, signature/stamp presence, boilerplate and unclassified regions. Each field needs raw text, original-image polygon, crop ID, alternatives, provenance and review state. Store translation/normalization separately and link it to the source span. Keep absent units, routes, durations and ambiguous dates unknown.
- Preserve full transcription privately; make pseudonymous sharing/FHIR an explicit approved projection. Transcribing a clinician-written diagnosis is different from making a diagnosis, but the existing policy excludes Condition export. Do not silently discard source text or bypass export policy.
- Cache OCR instances; replace English-only identifier heuristics with multilingual/multiline regions and editable opaque masking. Preview actual redacted pixels. Hosted backend OCR is local to the server, not the user's browser. Remote SAM currently receives the original before redaction.
- Make SAM optional for page/object geometry. It cannot perform handwriting recognition or link dosing instructions to medicines. Avoid generative restoration that may invent character strokes; retain raw/corrected views and coordinate transforms.
- Add a permitted, versioned Bangladesh brand catalogue adapter, preserving suggestions separately. RxTerms alone should not be assumed to cover local brands. Never select a drug from the presumed diagnosis or infer a strength unit from a bare number.
- Extend doctor review to source crops, all medication fields, conflicts and explicit unknowns; fix doctor redaction confirmation. Changes invalidate approval. Separate approval from external export.
- Assemble FHIR deterministically from approved fields. Add evidence and region-coverage checks; a valid bundle cannot certify its transcription. Private original/full transcript retention also requires access controls absent in this prototype.

Start with a proposed pilot of 50-100 representative prescriptions annotated by two qualified reviewers with disagreements adjudicated. Hold out doctors and clinics, include illegible cases, and compare critical-field errors, omissions, abstention behavior and correction time. This proposed pilot size does not establish statistical assurance. The public Gazipur dataset contains 1,000 bilingual prescriptions and states CC BY 4.0 licensing; review its README, redaction and split suitability before use. [Dataset v2](https://data.mendeley.com/datasets/tg2hm7n2bs/2).
